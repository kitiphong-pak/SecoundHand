# Backlog

งานที่ตกลงกันแล้วว่าจะทำ แต่ยังไม่ได้เริ่ม เรียงตามลำดับที่ตั้งใจทำ

## เก็บงานหลังย้ายไป Supabase Auth

ย้ายไปแล้วใน branch `feature/supabase-auth` (migration 018, [src/lib/supabaseAuth.ts](../src/lib/supabaseAuth.ts), [src/proxy.ts](../src/proxy.ts)) ที่เหลือคือ:

- **ลืมรหัสผ่าน / ยืนยันอีเมล** Supabase มีให้แล้ว แต่ SMTP ตั้งต้นของ Supabase ส่งได้เฉพาะอีเมลของสมาชิกทีมโปรเจกต์ ต้องตั้ง SMTP ของตัวเองก่อน (เช่น Resend หรือ SES) ตอนนี้สมัครผ่าน `admin.createUser` แบบถือว่ายืนยันอีเมลแล้ว เหมือนระบบเดิมที่ไม่มีการยืนยัน
- **PRD** ตอนปลุก PRD ต้องรัน `migrate:prd` ให้ถึง 019 ด้วย PRD ยังไม่มีผู้ใช้ จึงไม่ต้องย้ายผู้ใช้ และด่านตรวจใน 019 ผ่านได้เพราะมีแค่บัญชีระบบที่มี hash

## Flow ออเดอร์ใหม่ (ไม่ผ่านเงิน ไม่มี OTP)

ออกแบบและผ่านสภาที่ปรึกษาแล้ว ยังต้องตัดสินใจเรื่องการยืนยันเบอร์โทร แบ่งเป็น 4 phase

- ~~**Phase 1** (1a–1d) เอา OTP และการชำระเงินจำลองออก ออเดอร์เริ่มที่ `reserved` แต่ละคนจองได้ไม่เกิน 3 ชิ้น ลบ `disputed` และมีการ์ดนัดในแชทที่ไม่บังคับใช้~~ — ทำแล้วใน branch `feature/order-flow-phase1` (migration 020–023)
- **Phase 2** ยืนยันเบอร์โทร แจ้งว่าอีกฝ่ายไม่มาตามนัด และให้โต้แย้งได้ ประวัติไม่ถูกลบ
- **Phase 3** แสดงคะแนนมาตามนัด ทำเมื่อมีการนัดผ่านแอปอย่างน้อย 30% และมีผู้ใช้ที่นัดสำเร็จ 5 ครั้งขึ้นไป
- ตัวเลขทั้งหมดรวมไว้ที่ `config.ts` เช็คหมดอายุทั้งแบบ lazy ตอนอ่านข้อมูล และผ่าน cron

## ความเร็วของหน้าเว็บ (ยังไม่เร่ง วัดไว้แล้ว 23 ก.ย. 2026)

วัดจากเครื่อง dev กับ Supabase cloud — ตัวเลขนี้ใช้กับ production ด้วย ไม่ใช่ปัญหาเฉพาะตอน dev

- **หน้าสินค้ายิงไป Supabase ต่อกันเป็นทอดๆ 5–6 รอบ** (`getCurrentUser` 2 รอบ → product → seller → order) รอบละ ~100ms จากไทย ทั้งที่ product/seller/order ไม่ได้ต้องรอผลของกันและกัน — รวมเป็น `Promise.all` ได้
- **`Header` poll `/api/badges` ทุก 5 วิ ไม่หยุดตอนสลับแท็บ** ต่างจาก `OrderActions` ที่หยุดเมื่อ `document.hidden` แล้ว — เปิดหลายแท็บค้างไว้เมื่อไหร่ เซิร์ฟโดนยิงตลอดเวลาโดยไม่มีใครดู
- เซิร์ฟ dev ยิง 10 คำขอพร้อมกัน ได้คำขอละ 2.5 วิ (ยิงทีละอัน 0.35 วิ) — คำขอที่เพิ่งกดต้องต่อคิวหลัง poll ของแท็บอื่น
- `.next` เคยบวมถึง 1.2 GB แล้วทำให้กดหน้าแรกแล้วค้าง แก้ด้วย `rm -rf .next` ถ้าเจออีกให้สงสัยตัวนี้ก่อน

## หน้าแชท — ส่วนที่ยังเหลือ

รื้อรอบแรกทำไปแล้ว (24 ก.ย. 2026): เต็มความสูงจอ, จัดกลุ่มข้อความที่ส่งติดกัน, เส้นคั่นวัน,
รูปโปรไฟล์, สถานะอ่านแล้ว, ช่องพิมพ์หลายบรรทัดพร้อมปุ่มส่งเป็นไอคอน
(ตรรกะจัดกลุ่มอยู่ที่ [src/lib/chatGrouping.ts](../src/lib/chatGrouping.ts) มีเทสคุม)

ที่ยังไม่ได้ทำ:

- **ข้อความเด้งทันทีด้วย Supabase Realtime** — ตอนนี้ยัง poll ทุก 4 วินาที ความรู้สึก "เด้งทันที"
  แบบ Messenger ต้องใช้ realtime ซึ่งเป็นงานคนละก้อนกับการจัดหน้าจอ
- **เดสก์ท็อปสองคอลัมน์** รายการห้องซ้าย ห้องที่เปิดอยู่ขวา (ตอนนี้ยังเป็นคอลัมน์เดียวเหมือนมือถือ)
- **หัวแชทใส่รูปสินค้ากับสถานะออเดอร์** ตอนนี้มีแค่รูปโปรไฟล์กับชื่อคู่สนทนา

## ตั้งค่าของระบบ (รอให้มีของสะสมพอก่อนค่อยทำหน้าเดียวจบ)

ยังไม่ทำตอนนี้ — รอจนมีรายการมากพอที่จะคุ้มกับการมีหน้าตั้งค่าจริงๆ ไม่งั้นจะได้หน้าที่มีสวิตช์เดียว

- **ตั้งค่าแชท**: ขนาดตัวอักษร, ฟอนต์, สีพื้นหลัง/สีฟองข้อความ, ธีมของห้องแชท
- ที่พอมองออกตอนนี้ว่าจะมาอยู่รวมกัน: สลับธีมสว่าง/มืด (ตอนนี้อยู่ที่ปุ่มบน header),
  จังหวัดเริ่มต้นเวลาเปิดหน้าแรก, การแจ้งเตือน (ยังไม่มีระบบแจ้งเตือน)

## ก่อน deploy

- เอากล่องบัญชีทดสอบออกจากหน้า login
- มี privacy policy และ ToS รวมถึงนโยบายเก็บ/ลบข้อมูลสถานที่และเวลานัดตาม PDPA
- มีคำเตือนความปลอดภัยตอนนัดเจอ (มีแล้วในฟอร์มเสนอนัดในแชท ยังต้องมีในหน้าออเดอร์และตอนสมัคร)
- ปลุก PRD แล้วรัน `npm run migrate:prd`
- ตั้ง env บน Vercel ให้ครบ 4 ตัว รวม `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` ที่เพิ่มมาตอนย้าย auth
- ตอนสร้างโปรเจกต์บน Vercel ต้องตั้ง Production Branch เป็น `main` เอง
- **ห้ามรัน `npm run seed` กับ PRD** เพราะจะสร้างบัญชีที่ใช้รหัส `password123` รวมถึงบัญชีแอดมินด้วย
